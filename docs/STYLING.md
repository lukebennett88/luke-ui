# Styling

This guide defines how Luke UI authors and consumes styles. Keep component styles in recipes. Use
layout utilities for application structure. Use semantic variables for application-owned visuals.

## Cascade layers

The shipped stylesheet declares these layers in this order:

```css
@layer reset, theme, base, recipes, overrides, utilities;
```

`reset` scopes the reset to `.luke-ui-reset`. `theme` supplies the theme root and semantic tokens.
`base` contains shared component foundations. `recipes` contains component recipe output.
`overrides` is where compiled consumer `xstyle` output belongs. `utilities` contains application
utilities and deliberate overrides.

Recipe output is split into numbered sublayers inside `recipes`:

```css
@layer recipes {
	@layer priority1, priority2, priority3;
}
```

The authoring transform assigns each generated recipe atom to its numbered sublayer. Keep the
numbered order stable when adding recipe output. Retained Vanilla Extract rules that must beat all
generated recipe atoms belong directly in `recipes`.

Never author `!important` in a `recipes.priorityN` rule. Important declarations reverse layer
precedence, so a nested priority layer would outrank retained direct `recipes` CSS and consumer
`overrides`. Put forced or structural rules that need `!important` in retained CSS written directly
in `recipes`, with the reason documented at the call site. `LoadingSkeleton` is the retained forced
surface example.

Declare application layers before importing Luke UI styles. Import `@luke-ui/vite/stylesheet.css`
when the application uses `xstyle` so the `overrides` layer is declared. Import the Luke UI
stylesheet after it.

The stylesheet graph starts at `core/styles/index.css.ts`, which imports the layers, reset, theme
root, retained modules, component styles, and utilities. `core/styles/modules.css.ts` is the
committed registry for retained Vanilla Extract style modules. Keep its imports in code-point order.
`theme/tokens.stylex.ts` is generated by `scripts/generate-stylex-tokens.ts`. Edit the theme
contract and generator inputs rather than the generated file. Its nested `vars` object is the shared
token interface for recipes and the public theme export.

## Recipes

Author a single-part recipe with `recipe({ base, variants, defaultVariants, compoundVariants })`:

```ts
import { recipe } from '../styles/recipe-authoring.js';

export const buttonRecipe = recipe({
	base: { display: 'inline-flex' },
	variants: {
		size: {
			medium: { minBlockSize: 40 },
		},
	},
	defaultVariants: { size: 'medium' },
	compoundVariants: [{ size: 'medium', style: { gap: 8 } }],
});
```

`base` is the shared style. `variants` maps a group to named values. `defaultVariants` supplies a
value when a caller omits that group. `compoundVariants` uses variant keys as conditions and a
`style` value for the matching combination. The API follows the Tailwind Variants compound variant
shape.

Use `RecipeSelection<typeof buttonRecipe>` for the variant selection type. The recipe call returns
the full `stylex.props(...)` result. Spread that result onto the element.

Slotted recipes add a `slots` map. Base and variant values map slot names to styles:

```ts
export const fieldRecipe = recipe({
	slots: {
		root: { display: 'flex' },
		label: { fontWeight: 600 },
	},
	variants: {
		size: {
			medium: { root: { gap: 8 } },
		},
	},
});
```

A slotted recipe returns one props object per slot. A variant may provide a partial slot map. Omit
slots that the variant does not change. Use `RecipeSelection<typeof fieldRecipe>` for its variant
selection type.

Recipe style entries may be inline StyleX objects, compiled styles from `stylex.create`, or ordered
arrays mixing those forms. Wrap imported compiled styles with `compiledStyle()` and imported arrays
with `compiledStyleList()` in an array spread. Keep arrays ordered when two entries set the same
property.

## `xstyle`

Expose `xstyle?: XStyleProps['xstyle']` on a component when consumers need a supported one-property
override. Pass it to the recipe, then compose the recipe result with the consumer's `className` and
`style`:

```tsx
const { className, style, xstyle, ...elementProps } = props;
const recipeProps = buttonRecipe({ xstyle });

return <button {...elementProps} {...composeRecipeProps(recipeProps, { className, style })} />;
```

`composeRecipeProps` appends the consumer's `className` after the recipe's and lets the consumer's
inline `style` win per property. Use `composeRacRecipeProps` instead when the element is a React
Aria Component, so its function-valued `className` and `style` render props still resolve.

For a slotted component, pass a partial map such as `{ label: labelStyle }` to the recipe and spread
the returned props on the matching elements. Keep `xstyle` on the public presentation element. Do
not use it to reach into internal DOM.

`xstyle` replaces a recipe declaration for the same property. A narrow StyleX limitation remains: an
`xstyle` `padding` or `paddingInline` shorthand does not replace recipe `paddingInlineStart` or
`paddingInlineEnd`. Use the matching logical longhand for those padding overrides.

Luke UI supports left-to-right and right-to-left direction under `writing-mode: horizontal-tb`. It
does not support vertical or sideways writing modes. Author flow-relative CSS with camelCase logical
StyleX keys such as `inlineSize`, `marginInlineStart`, and `insetInline`. Do not use quoted
kebab-case property keys. StyleX lowers bidi-insensitive logical properties such as `inlineSize` and
`marginBlockStart` to physical CSS. Direction-sensitive properties must remain logical so
`direction: rtl` keeps the intended result.

## Layout utilities

`createSprinkles(props)` returns `{ className, style }`. Spread or merge the complete result so
dynamic values in `style` are preserved. Use responsive objects with `initial`, `bp640`, `bp768`,
`bp1024`, `bp1280`, or `bp1536`. Each name selects a container-query breakpoint.

When composing utility output with other props, use `mergeStyleProps` from `@luke-ui/react/utils`.
It concatenates `className`, shallow-merges `style`, and lets the later props overwrite other keys —
it does not chain event handlers. At a React Aria `render` boundary, pass the resolved DOM props
through to the element and merge them with utility output. Use React Aria Components' `mergeProps`
when that composition also needs its event-handler chaining behaviour.

## Static styles and tokens

Import `@luke-ui/react/stylesheet.css` and one bundled theme stylesheet. Apply the theme
`rootClassName` to the application root. Do not inject styles at runtime.

Use `Box` and utilities from `@luke-ui/react/styles` for layout. Use the public `vars` contract for
application-owned custom UI. Do not target generated recipe selectors or implementation-state
attributes such as `data-pressed`.
