A Luke UI theme is a static stylesheet. It defines the visual foundation for a themed subtree. It
does not change a component's API or behaviour.

## Theme foundations

A themed subtree starts at one root. The root carries `themeRootClassName` and one identity class,
such as `tactileThemeClassName`. `themeRootClassName` supplies the reset and the base theme layer.
The identity class supplies the semantic values for that subtree.

The identity generates those values. It provides semantic colour, typography, spacing, radii,
material, and depth for both light and dark modes. A colour mode selects one side of those values.

A nested scope changes mode, or starts a new root, for one part of a page. Colour-mode scopes nest.
Identity classes do not. Use a second identity only on a new root beside the first scope, never
inside it.

Read [Applying a theme](/applying-a-theme) for the exact imports, classes, and colour-mode rules.

## Theme identities

Luke UI ships two bundled identities:

- Tactile is the default. It uses stronger depth and a compact material treatment.
- Paper is flatter, with lighter borders and depth.

Use one identity for an application or an independent themed subtree.

## Component variants

Themes define the visual system. Components define the choices a developer can make within it. For
example, Button controls its own `tone`, `appearance`, size, pending state, and accessible
behaviour. The theme supplies the semantic values behind those choices.

```tsx
<Button appearance="solid" tone="accent">
	Save changes
</Button>
```

Use a component API before custom CSS. Use a custom theme when the product needs different global
colours, type, radii, or depth.

## Semantic tokens

The active theme exposes a typed, public `vars` contract. Use it when a custom element sits beside
Luke UI components.

Read [Token reference](/token-reference) for the full contract. Read [Colour](/color) for the
semantic roles it exposes.
