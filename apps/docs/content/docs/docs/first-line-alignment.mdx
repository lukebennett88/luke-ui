Use `startContent` and `endContent` on [Text](/components/typography/text#adornments) or
[Heading](/components/typography/heading#adornments) to align an icon, avatar, or control with the
capitals of the first line. Use [Box](/components/layout/box) or
[Cluster](/components/layout/cluster) when the whole content box determines the alignment.

Resize a preview to see wrapping. The examples use the docs theme, its Inter webfont, and its
Capsize trims.

## Inline and block flow

The default `span` keeps adornments in sentence flow. Its wrapped lines may return beneath the
leading adornment, and its trailing adornment follows the final word. Block element types hang
wrapped lines after `startContent` and keep `endContent` beside the first line.

## Compound content

Use `Text elementType="div"` around a `Stack` for a title and description beside adornments. The
adornments follow the outer Text's typography, so set the title's style as `typography` on the outer
Text and set `shouldInheritFont` on the title. The description stays in the same content column.
[Text](/components/typography/text#compound-content) explains the rule. Clamp a title or description
on its own Text rather than clamping the compound wrapper.

## Trailing actions

An `IconButton` in a paragraph's `endContent` joins its keyboard order after the text. Place a
heading's action beside the heading, because action text inside a heading joins its accessible name.

## Spacing

`gap` accepts a spacing token or responsive values with `initial`. The default is `sp4` for inline
text and `sp8` for block text. Responsive values follow the nearest ancestor size container. See
[Responsive values](/docs/layout#responsive-values).

## General layout alignment

Use `Box` to align the edges or centres of whole content boxes. Use `Cluster` when the items should
wrap. Choose semantic elements such as `li` when the row belongs to a list.

## Limitations

<ExampleBlock src="first-line-alignment/limitations" title="First-line alignment: Limitations" />

- A separate sibling description does not hang under a title's text. Put both in a compound Text
  when they need the same content column.
- Inline text does not hang. Its wrapped lines may start under the adornment.
- `textAlign="center"` centres the text in the space beside the adornment.
- An adornment taller than the first line moves the text down to stay centred on it.
- Adornments take phrasing content. Use a layout primitive for arbitrary block content beside text.
- A browser without the `cap` unit centres adornments on the x-height instead.
- Compound adornments centre on the first line only when it uses the outer Text's typography. They
  do not align independently with several text runs.

## Measure in this browser

Each value is the distance from a graphic's centre to its line's capitals, or between two baselines.
The compound fixtures measure the avatar against a cap probe in a title that uses the outer Text's
typography. The readout waits for `document.fonts.ready` and records once per page load.

<ExampleBlock src="first-line-alignment/readout" title="First-line alignment: Readout" />

To compare a browser:

1. Open `/docs/first-line-alignment` in the target browser and wait for the numeric readout and
   environment row. Offsets near `0px` show closer measured alignment. Resize the span and paragraph
   previews to compare inline wrapping with hanging lines and the position of `endContent`.
2. In Inline composition, check the link underline at rest, on hover, and after focusing with Tab.
   Inspect Compound content, Long text and line clamping, Graphics and text, Spacing, and
   Right-to-left. In DevTools, block requests for Inter `.woff2` files and reload, then unblock them
   and reload again.
3. Reload after changing fonts or the theme. The `1cap` probe reports the selected font's cap
   geometry. It does not prove fallback metrics match the theme's Capsize trims or verify underline
   painting.
