This page belongs to an exploratory spike for
[#801](https://github.com/lukebennett88/luke-ui/issues/801). It compares the current
[Track](/components/layout/track) with `startContent` and `endContent` on
[Text](/components/typography/text) and [Heading](/components/typography/heading). Neither is
settled API.

Resize a preview to see wrapping. The examples use the docs theme, its Inter webfont, and its
Capsize trims.

## How the candidates align

A first line has its own font size, line height, and trim. CSS cannot read those from a sibling, so
content beside the text can only match them by sharing the text's typography.

- **Track `firstLine`** sizes each rail to one line of Track's inherited line height. A child that
  sets its own typography, such as a `Heading`, moves the line away from the rail. A trimmed child,
  such as `Text` with `elementType="p"`, moves its first line up by its trim, even with the same
  type style.
- **Text adornments** render inside the text element, so they inherit its typography. Each adornment
  sits in a box centred on the capitals of its line, whatever it contains.
  - A block element type, such as `p`, `div`, or a heading, lays the adornments and the text out in
    a row. Wrapped lines hang after `startContent`, and `endContent` sits at the end of the first
    line.
  - An inline element type, such as the default `span`, keeps the adornments in the flow of the
    text. The text breaks with its sentence, and a link's underline carries through it.

## Heading with a leading icon

The heading is trimmed, wraps, and uses `heading3`. Track around the heading puts the icon about 4px
below the first line. Track inside the heading comes within 1px but needs `elementType="span"`.
`startContent` needs neither.

## Compound content

An avatar beside a title and a description is not one run of text, so the description does not hang
under the title. Track still lays this out. `firstLine` lets the taller avatar overflow above the
row. `start` aligns the avatar with the top of the content, and `center` with its middle.

<ExampleBlock src="first-line-alignment/compound" title="First-line alignment: Compound content" />

## Trailing actions

An `IconButton` in `endContent` lines up with the first line of a paragraph and joins its keyboard
order after the text. A heading should not contain an action, because its text joins the heading's
accessible name. Place the action beside the heading in a row aligned on baselines instead.

<ExampleBlock src="first-line-alignment/action" title="First-line alignment: Trailing actions" />

## Long text and line clamping

The text shrinks below its longest word, so an unbroken URL wraps inside the row. `lineClamp` clamps
the text and keeps the adornments.

<ExampleBlock src="first-line-alignment/overflow" title="First-line alignment: Long text" />

## Inline composition

An inline `Text` with adornments stays in its sentence and breaks across lines with it. Track as a
`span` is one box, so a text link around it loses its underline. `Button` and `Link` with
`appearance="button"` already take `startContent` and `endContent`.

## Type styles and icon sizes

Each row pairs a type style with an icon size. Track centres the icon in one body line, and each
trimmed paragraph moves up inside it, so the icon sits up to 8px below the first line.

<ExampleBlock src="first-line-alignment/scale" title="First-line alignment: Type styles" />

## A row nested in the text

A narrower alternative leaves `Text` unchanged and nests a row inside it, as Track does with
`elementType="span"`. The nested row cannot be clamped by the outer `Text`, measures the wrong line
when its content sets its own typography, and stops a link's underline.

<ExampleBlock src="first-line-alignment/narrower" title="First-line alignment: Nested row" />

## Limitations

These cases show where Text adornments fall short or behave in ways to weigh before adopting them.

<ExampleBlock src="first-line-alignment/limitations" title="First-line alignment: Limitations" />

- Adornments hang the text of their own element. A description in a sibling element does not hang.
- Inline text does not hang. Its wrapped lines start under the adornment, as in a sentence.
- `textAlign="center"` centres the text in the space beside the adornment, not as a group with it.
- An icon taller than the line moves the first line down to stay centred on it.
- Adornments sit in a `span`, so they take phrasing content.
- Adornments move by the `cap` unit. A browser without it centres them on the x-height instead.
