Luke UI defines semantic typography styles. Each style is a complete treatment: font family, size,
weight, line height, letter spacing, and Capsize trim.

## Base components

Use `Text` for body copy and other non-heading content. Use `Heading` for document and section
headings. Heading manages semantic levels and selects a matching typography style by default.

<ExampleBlock src="overview/typography-components" title="Typography: Base components" />

Use `Numeral` for locale-aware values. It inherits the typography styles. It formats currencies,
percentages, units, and compact values. Use `Emoji` when an emoji needs a reliable accessible label.

## Typography styles

`Text` and `Heading` use these styles, from smallest to largest:

| Style                 | Intended use                                              |
| --------------------- | --------------------------------------------------------- |
| `caption`             | Ancillary text at the smallest size                       |
| `label`               | Terse UI and control text at label size with label weight |
| `body`                | Normal body copy                                          |
| `lead`                | Larger introductory body copy                             |
| `heading4`–`heading1` | Visual heading hierarchy                                  |
| `display`             | Oversized editorial or marketing moments                  |

<ExampleBlock src="text/typography" title="Typography: Styles" />

`Text` defaults to `body`. `Heading` selects a style from its level, and accepts `typography` when
the visual hierarchy needs a deliberate override. An `h2` can use `heading3` visually without
changing its semantic level. There is no `heading5` or `heading6` style. Those HTML levels reuse
`lead` and `body` with heading weight.

## Capsize trims

Each style includes Capsize trim values for its font. A line box normally reserves space above and
below its letters. Trim removes that extra space from a block text element. Read
[Text](/components/typography/text#trimming) for how `Text` infers trim from the element type.

Trim values belong to `Text`. They are not public tokens. Render trimmed custom text with `Text` and
its `elementType` rather than recreating the trim in application CSS.

## Weight and colour

Each typography style already carries its weight. Pass `fontWeight` only when you need a different
role. Themes expose `body`, `label`, `heading`, and `emphasis` for that purpose, and for `Strong`.
Text also accepts semantic `color` values such as `primary`, `secondary`, `accent`, `info`,
`success`, `warning`, and `danger`.

```tsx
<Text color="secondary" typography="label">
	Last updated 12 minutes ago
</Text>
```

## Fonts

A theme names a body font and, optionally, a display font. The body font sets `caption`, `label`,
`body`, and `lead`. The display font sets `heading4` through `heading1` and `display`. Without a
display font, every style uses the body font. `vars.font.family.body` and `vars.font.family.display`
expose the two families.

Tactile and Paper use Inter for every style. Read [Authoring a theme](/docs/authoring-a-theme#fonts)
to set and load the fonts of your own theme.

Each style's trim comes from the metrics of the first font in its stack. The trim is exact only
while that font renders:

- With `font-display: swap`, a fallback font shows until the first font loads. Trims are slightly
  off until then.
- A system stack such as `-apple-system, BlinkMacSystemFont, system-ui, sans-serif` resolves to a
  different font on each platform. Its metrics describe one of them, so trims are exact only on the
  platforms that use that font.

### Code font

`Code` uses `vars.font.family.code`, a system monospace stack that every theme declares. To use
another font, override the variable on `:root` in an unlayered rule after the theme stylesheet:

```css
:root {
	--luke-font-family-code: 'JetBrains Mono', ui-monospace, monospace;
}
```
