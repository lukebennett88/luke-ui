---
title: Applying a theme
description: Load a theme, set its identity class, and choose colour modes.
---

A themed document needs the shared Luke UI stylesheet, one theme stylesheet, and that theme's
identity class on `<html>`. Theming is static CSS, so it needs no provider.

## Load the theme

Import `@luke-ui/react/stylesheet.css` and the theme's stylesheet. Import the theme's `fonts.css` to
load its font, or load that font another way. Render the theme's identity class on `<html>` and
`rootClassName` on `<body>`. When the application renders on the server, render both there too.

<SourceCodeBlock src="theming/getting-started" />

The identity class selects the theme's tokens. `rootClassName` adds the reset and base typography,
and works the same way for every theme.

## Use one identity class

Set exactly one identity class, on `<html>`. An identity class on any other element does nothing.
Two identity classes on `<html>` are not supported: the themes' rules compete, and stylesheet order
decides which values win. To switch themes at runtime, replace the class rather than adding a second
one.

## Choose a colour mode

Without a colour mode, the document follows the system preference, and changes with it live. Set
`data-color-mode="light"` or `data-color-mode="dark"` on `<html>` to fix the mode for the whole
document.

<SourceCodeBlock src="theming/apply-theme" />

The theme sets the native `color-scheme` property for each mode. Browser controls and scrollbars
then match the Luke UI content.

System mode exists only at the document level, and it means no attribute. When a preference control
offers "System", remove `data-color-mode` from `<html>`. Do not resolve the preference to `light` or
`dark` yourself, because the attribute would then stop following a later system change. Only
lowercase `light` and `dark` are valid values.

## Set the mode before first paint

Render the identity class, and any explicit mode you know on the server, in the initial HTML. When
the mode comes from a stored client-side preference, set it with an inline script in `<head>`,
before the page paints. The script sets `data-color-mode` only for an explicit choice.

<SourceCodeBlock src="theming/color-mode-script" />

The script changes `<html>` before React hydrates it. In a React application that renders `<html>`,
set `suppressHydrationWarning` on it.

## Nest colour-mode scopes

Set `data-color-mode` on any element below `<html>` to fix the mode for that subtree. Scopes nest to
any depth, and the nearest explicit scope wins.

	layout="full-bleed"
/>

<SourceCodeBlock src="theming/nested-color-mode" />

The shared stylesheet repaints each scope with its mode's text colour, accent colour, and base
surface. Your own CSS and Luke UI components outrank that repaint, so a scope element can still set
its own background.

`<body>` can be a scope too. Its background paints the whole page canvas, but page scrollbars follow
`<html>`. Set a mode for the whole document on `<html>` instead.

### Override a token on a scope

A token you override on an element that carries `data-color-mode` loses to the theme's explicit-mode
rule, which has a specificity of (0,2,0). Override the token on a child element, or use a more
specific selector, such as `.app .sidebar[data-color-mode]`.

## Overlays in a scope

An overlay renders into `document.body`, outside the scope around its trigger. Luke UI's own
overlays handle this. The `Select` popover, the `Combobox` popover, and the `Combobox` tray copy the
trigger's mode from the nearest scope below `<html>` onto the overlay. Without such a scope, the
overlay follows the document.

Luke UI copies the trigger's colour mode onto the overlay when the overlay element is created. It
doesn't update while the overlay stays mounted.

To give one of these overlays its own mode, pass `data-color-mode` to the overlay primitive, such as
`ComboboxPopover` or `SelectPopover`. Your value wins, even when it matches the document mode.

### React Aria overlays

A React Aria overlay that you render yourself does not copy the mode. When one can open inside a
scope, set the scope's mode on the overlay too.
