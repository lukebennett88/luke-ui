title: Authoring a theme
description: Compile a curated theme input into a static Luke UI theme stylesheet.
---

Author a custom theme when Tactile and Paper do not suit the product. `defineTheme` turns a small,
curated `ThemeInput` into static CSS for one theme with light and dark modes. It runs at build time
in Node 24 or later, and needs no browser and no Luke UI release.

Import every authoring API from `@luke-ui/react/theme/compiler`. Never import it from application
code that runs in the browser. The application imports only the compiled stylesheet and
`@luke-ui/react/theme`.

## Define the input

A basic theme authors an accent colour, a neutral character, and a body font. Everything else
defaults. A `ThemeInput` includes:

- a kebab-case `name`
- `typography.fonts.body`, the required body font
- `color.accent`, the required brand or interaction accent
- `color.neutral` or `color.neutralStyle` (`'cool'`, `'neutral'`, or `'warm'`) for the neutral base
  anchor
- optional `color.surface` colours for the `base`, `subdued`, `field`, and `overlay` surfaces
- optional `color.info`, `color.success`, `color.warning`, `color.danger`, `color.focus`, and
  `color.backdrop`
- optional `typography.fonts.display`, `typography.fontWeight`, `radius`, `depth`, and
  `controlFinish`

Most source colours accept one string or a `{ light, dark }` object. Either side of the object may
be omitted. How each colour treats them differs:

- `accent`, `neutral`, and `surface.base` adapt one string to each mode: they keep its hue and
  chroma and choose a lightness for the mode. A missing side is adapted from the side you set.
- `info`, `success`, `warning`, `danger`, `focus`, and `backdrop` use one string as written in both
  modes. A missing side uses Luke UI's default for that mode.
- `surface.subdued`, `surface.field`, and `surface.overlay` take only the object, because one value
  cannot suit both modes. A missing side is generated from `base`. See [Surfaces](#surfaces).

`color.backdrop` is the one colour that may include alpha. Luke UI emits it as
`color.overlay.backdrop`. Hover and pressed colours are generated from the resting semantic colours.
Do not author them.

`radius` overrides the `detail`, `control`, `surface`, and `overlay` corners, which default to 4, 8,
12, and 16px. Radius inputs are pixels at a 16px root and emit as `rem`. `depth` and `controlFinish`
can be set per mode and per rung. An omitted `depth` rung uses a subtle default shadow, and an
omitted `controlFinish` rung is `none`. Typography sizes, line heights, letter spacing, and motion
are not authored. Read [Fonts](#fonts) for the font input.

### Fonts

Each font is a `ThemeFont`: an authored CSS `family` stack, and Capsize `metrics` for the stack's
primary font. Luke UI trims each typography style with its font's metrics. Take metrics from
`@capsizecss/metrics`, or read them from a font file with `@capsizecss/unpack`. `FontMetrics` from
`@luke-ui/react/theme/compiler` types a full metrics object.

`typography.fonts.body` sets `caption`, `label`, `body`, and `lead`. The optional
`typography.fonts.display` sets `heading4` through `heading1` and `display`. Without a display font,
those styles use the body font.

<SourceCodeBlock src="theming/display-font" />

A theme names its fonts but does not load them. Load every font, and every weight, the theme uses.
Read [Typography](/docs/typography#fonts) for how font loading affects trims.

`typography.fontWeight` sets the `body`, `label`, `heading`, and `emphasis` weights, which default
to 400, 500, 600, and 700.

### Surfaces

`color.surface.base` is the application background. The neutral and role colours are generated from
it. When you omit it, it uses the neutral colour.

Every other surface is a fixed lightness offset from `base` for the mode. Set `subdued`, `field`, or
`overlay` when a default does not suit the theme. Luke UI maps an authored colour into the sRGB
gamut but never changes its lightness to pass contrast. If a surface fails
[contrast validation](#contrast-validation), set it explicitly or choose a different value.

## Extend a theme

Set `extends` to another theme's input. Your theme inherits every value it does not set. Each theme
package exports its input as `theme` from `./input`, such as `@luke-ui/theme-paper/input`.

<SourceCodeBlock src="theming/extend-bundled-theme" />

Your theme always declares its own `name`. Two themes with one name emit a colliding identity class.

What each section inherits:

- `color` merges role by role. A role replaces the base's role whole.
- `color.neutral` and `color.neutralStyle` are one decision. Setting either replaces the base's
  neutral decision.
- `radius` and `typography.fontWeight` merge key by key.
- `typography.fonts` merges font by font. A font replaces the base's font whole, so a family never
  pairs with another font's metrics. Set `display: null` to remove an inherited display font.
- `color.surface` merges surface by surface. A surface replaces the base's surface whole.
- `depth` and `controlFinish` merge per mode, then per rung.

A value set to `undefined` counts as omitted and inherits.

A theme may extend a theme that extends another. A cycle throws.

An extending theme compiles to a complete stylesheet of its own, so load it instead of the base
theme's stylesheet. It still names the base's fonts, so keep loading them. With a theme package,
keep importing its `fonts.css`.

Contrast validation runs on the merged theme. `ThemeContrastError` carries `inheritance`, naming the
chain of themes and which colours came from a base.

## Generate a stylesheet

`defineTheme` returns the stylesheet as a string. Write it to a file with a Node script, and run the
script whenever the input changes.

<SourceCodeBlock src="theming/compile-theme" />

Node 24 runs this script as TypeScript directly, within these limits:

- It strips types without compiling, so the script and every module it imports use erasable syntax
  only. Enums and namespaces fail.
- The nearest `package.json` `"type"` field decides whether a `.ts` file loads as ES modules or
  CommonJS. Use `"type": "module"` for top-level `await`.
- Relative imports name the `.ts` extension. Enable `allowImportingTsExtensions` or
  `rewriteRelativeImportExtensions` in `tsconfig.json` so TypeScript accepts it.
- `tsconfig.json` path aliases do not resolve.
- Every dependency the script imports ships JavaScript.

Load the generated stylesheet, set the theme's identity class on `<html>`, and apply
`rootClassName`, exactly as for [Tactile or Paper](/docs/applying-a-theme). The class is
`luke-ui-theme-` followed by the theme's `name`. `getThemeClassName` from `@luke-ui/react/theme`
returns it.

## Validation

`defineTheme` validates each input in an `extends` chain on its own, then checks the merged theme
for a body font. It reports every problem at once. `ThemeValidationError.issues` lists each one with
the `theme` that contains it, the `path` within that theme, and a `message`. A base theme with an
invalid font fails even when your theme replaces that font.

A font `family` must not contain `;`, `{`, `}`, `<`, control characters, or an unclosed quote. Font
metrics must be finite numbers, with a positive `unitsPerEm`, `capHeight`, and `ascent`, a `descent`
of 0 or less, and a `lineGap` of 0 or more. Font weights are numbers from 1 to 1000.

## Contrast validation

`defineTheme` checks the generated colours against WCAG 2.2 in both modes. Content and controls can
sit on any surface, so every surface check covers all four: `base`, `subdued`, `field`, and
`overlay`.

At 4.5:1:

- `color.text.primary` and `color.text.secondary` against every surface.
- Each role's rest, hover, and pressed foreground against every surface and that role's subtle
  backgrounds.
- Each role's `onSolid` foreground against its solid backgrounds.

At 3:1, against every surface:

- `color.border.focus`, the focus ring.
- `color.border.control` and `color.border.controlHover`, the boundary of a form control.
- `color.background.danger.solid.rest`, the boundary of an invalid control.

If any pair fails, `defineTheme` throws `ThemeContrastError` instead of returning CSS. Its
`failures` array names the colour mode and both tokens of each failing pair. When a failing pair
names a surface, set that surface explicitly.

Role borders, such as `color.border.accent`, and `color.border.decorative` never fail validation.
Never rely on one alone to show a required state such as selected, invalid, or checked. Pair it with
text, an icon, or one of the colours above.

### When an accent cannot be used

`defineTheme` throws `ThemeGenerationError` when a role's solid colour cannot carry 4.5:1 `onSolid`
text. Some lightnesses have no near-white or near-black text that reaches 4.5:1. When you author one
accent string, `defineTheme` keeps its hue and chroma and searches for a lightness that works. An
accent side you set explicitly is used as written, so choose a lightness that works, or author one
string and let `defineTheme` adapt it.
