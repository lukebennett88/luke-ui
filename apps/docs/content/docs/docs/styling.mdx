Luke UI ships static CSS. It does not inject styles at runtime. Import the shared stylesheet and a
theme stylesheet once. Then use component props for the variations each component supports.

## Choose a styling approach

Work from the most specific public API to the broadest one.

1. Use a component's props for its supported appearance, size, state, and behaviour.
2. Use layout utilities for spacing, sizing, and responsive structure around components.
3. Use semantic variables for application-owned custom UI when no component fits.
4. Author a custom theme when the product needs a different visual foundation everywhere.

Read [Composition](/docs/composition) when the choice is between a component and a documented
primitive rather than between styling mechanisms.

| Guidance | Practices                                                                                  |
| -------- | ------------------------------------------------------------------------------------------ |
| Do       | Use a supported component prop for its appearance, size, state, or behaviour.              |
| Do       | Use a layout utility for its element contract, and `vars` for application-owned custom UI. |
| Don't    | Target generated selectors or undocumented state attributes.                               |

Do not override component recipe selectors or target state attributes unless the component documents
that attribute as part of its supported DOM contract. Many React Aria attributes are implementation
details and can change without a migration path. When a component deliberately exposes a state
attribute for styling or integration, treat it as public for that component only.

### Start with component props

Components are intentionally opinionated. Their public props cover supported variants, states, and
behaviour. The active identity supplies semantic colours, font roles, radii, and depth. Luke UI
defines its type and spacing scale in source.

### Apply a component recipe

Import a recipe when you own the element and need that component's visual treatment. Use the
component when you want its behaviour as well.

Use a recipe only when the component cannot render the element you need to style. For button-shaped
navigation, prefer [`Link`](/components/actions/link) with `appearance="button"` over applying
`buttonRecipe` to an anchor.

Each recipe lives on the component or primitive entrypoint that owns it. Import `buttonRecipe` from
`@luke-ui/react/button`. There is no `@luke-ui/react/recipes` barrel.

Recipes follow a fixed name. The function is the component in camel case plus `Recipe`. The variants
type is the component in Pascal case plus `RecipeVariants`.

The example shows how to apply a component treatment to an owned element:

<ExampleBlock src="styling/button-recipe" title="Styling: Apply a component recipe" />

A single-part recipe such as `buttonRecipe` returns the finished class string. Pass the same variant
names the component accepts, plus an optional `className` of your own. The recipe appends your class
after its own, so do not wrap the result in another composition helper.

```tsx
import { buttonRecipe, type ButtonRecipeVariants } from '@luke-ui/react/button';

const variants: ButtonRecipeVariants = {
	appearance: 'button',
	tone: 'neutral',
	prominence: 'standard',
};
const className = buttonRecipe({ ...variants, className: 'my-class' });
```

A slotted recipe returns one function per part. Choose variants once at the outer call, then call
the part you are styling with an optional `{ className }`. Recipes that style a component's private
multi-part anatomy stay package-private. Compose the public primitives instead of importing those
recipes.

A primitive's recipe imports from the primitive's entrypoint. `textInputRecipe` styles an input you
own:

```tsx
import { textInputRecipe } from '@luke-ui/react/primitives/text-input';

<input aria-label="Example input" className={textInputRecipe({ size: 'medium' })} />;
```

Do not import a recipe to restyle a Luke UI component from the outside. Use the component's props
for supported variation.

### Use layout components for structure

`Box` and the other layout components handle spacing, sizing, positioning, and responsive structure
around components. They do not set semantic colour, typography, or pseudo states. Read
[Layout](/docs/layout) for the full API.

### Use semantic variables for custom UI

The public `vars` token contract lets an application-owned element follow the active theme.

The token contract is public. Component selectors, generated palette values, and theme
implementation details are not. See the [token reference](/docs/token-reference) for the full
contract.

### Change the visual foundation with a custom theme

Use a [custom theme](/docs/authoring-a-theme) when a product needs a different identity, typeface,
or semantic colour system. `defineTheme` produces a static stylesheet for the full semantic contract
from a curated accent and neutral character. It is not a per-component override tool.

## Set up static styles

Luke UI's styles are static CSS: the shared stylesheet and one theme stylesheet. Read
[Applying a theme](/docs/applying-a-theme) for the imports, the identity class, colour modes, and
overlays.

The shared stylesheet gives the whole document a small baseline:

- **Document.** `<body>` gets the theme's base surface, text colour, accent colour, and body font, a
  unitless `1.5` line height, and no margin. Its background fills the page, including short pages
  and overscroll.
- **Colour-mode scopes.** An element with `data-color-mode` is repainted with its mode's surface,
  text colour, and accent colour.
- **Box sizing.** Every element and pseudo-element uses `border-box`.
- **Form controls.** Buttons, inputs, selects, and text areas inherit the surrounding font and have
  no margin. They keep their native appearance otherwise.
- **Focus.** Keyboard focus shows a 2px ring in the theme's focus colour, offset by 2px. In forced
  colours mode it uses the system highlight colour.
- **Container queries.** The root element is an inline-size container, so an unnamed `@container`
  query measures the page width.

Everything else keeps its browser presentation. Headings keep their sizes, lists keep their markers,
and paragraphs, tables, and native buttons keep their spacing. Luke UI components style themselves,
so they look the same in any page. The stylesheet does not change animations, including under
reduced motion. Each Luke UI component adapts its own motion.

Override any of these defaults with your own CSS, for example a `body` rule in your stylesheet.
Component state attributes such as `data-focus-visible` and `data-pressed` are implementation
details, not styling hooks.

## Use application CSS alongside Luke UI

Luke UI's stylesheet puts every rule in cascade layers. It declares a `base` layer for the
application, followed by a `luke-ui` layer for its own styles:

```css
@layer base, luke-ui;
```

Luke UI never writes to `base`. Put application defaults, such as a CSS reset, in `base` so Luke UI
component styles outrank them. Styles in a layer declared after `luke-ui`, and styles in no layer,
outrank all of Luke UI.

### Tailwind CSS

Declare one layer order before importing Tailwind or Luke UI:

```css
@layer theme, base, luke-ui, components, utilities;

@import 'tailwindcss';
@import '@luke-ui/react/stylesheet.css';
@import '@luke-ui/theme-tactile/stylesheet.css';
```

Without that statement, import order decides whether Tailwind utilities or Luke UI styles win. With
it, Tailwind Preflight stays below Luke UI components, and Tailwind utilities override Luke UI
component styles. Preflight still resets native HTML on its own, for example heading sizes and list
markers, whatever Luke UI does.

### Application styles

Tailwind utilities, CSS Modules, and application CSS work well for application-owned layout and
custom elements. Put Tailwind classes on surrounding elements or `Box`. Use CSS Modules or
application styles with public semantic variables for custom UI. Unlayered application CSS sits
outside Luke UI's layers, so do not use it to reach into a component's internal DOM.

```tsx
import { Box } from '@luke-ui/react/box';

<Box className="mx-auto" maxInlineSize="64rem" paddingInline="sp16">
	{children}
</Box>;
```

When a CSS Module or application stylesheet needs a token, use the stable `--luke-*` variable listed
in the [token reference](/docs/token-reference). Do not couple application CSS to undocumented
selectors or implementation attributes.
