TanStack Form owns the form state, and Luke UI renders the controls.

## Initialise the form

Call `useForm` with `defaultValues` and a submit handler. `revalidateLogic` holds validation back
until the first submit, then revalidates each field as it changes.

```tsx
const schema = z.object({
	email: z.email('Enter a valid email address.'),
	name: z.string().min(1, 'Enter your name.'),
});

const form = useForm({
	defaultValues: { email: '', name: '' },
	onSubmit: ({ value }) => saveAccount(value),
	validationLogic: revalidateLogic({ mode: 'submit', modeAfterSubmission: 'change' }),
	validators: { onDynamic: schema, onSubmit: schema },
});
```

TanStack Form accepts any Standard Schema validator, so Zod needs no resolver package. The form's
value types come from `defaultValues`, and TypeScript checks the schema against them.

## Integrate components

Wrap the fields in Luke UI's [`Form`](/components/forms/form). Set `validationBehavior="aria"` so
TanStack Form controls validation without browser submission blocking it. When every required field
should show a clear marker, set `necessityIndicator="required-label"`.

Give `form.Field` a `name` and a children function. Pass `field.state.value`, `field.handleChange`,
and `field.handleBlur` to the control, and pass `field.name` as the HTML `name`. Set `isRequired` on
fields the schema requires. Schema validation does not set required control semantics on its own.

Pass the current validation message from `field.state.meta.errors` to `errorMessage`. A non-empty
message marks the field invalid.

## Focus the first invalid field

TanStack Form leaves focus where it is after a failed submission. Hold a ref to the Form element and
search it for the first control marked `aria-invalid` from `onSubmitInvalid`.

```tsx
const FOCUSABLE_SELECTOR =
	'input:not([type="hidden"]), select, textarea, [tabindex]:not([tabindex="-1"])';

function focusFirstInvalidField(form: HTMLFormElement | null) {
	const invalid = form?.querySelector('[aria-invalid="true"]');
	if (!invalid) return;
	const control = invalid.matches(FOCUSABLE_SELECTOR)
		? invalid
		: invalid.querySelector(FOCUSABLE_SELECTOR);
	if (control instanceof HTMLElement) control.focus();
}
```

`TextInputField`, `CheckboxField`, `SwitchField`, and `ComboboxField` each mark the control itself,
so the first branch matches. The second branch covers a grouped control that marks a wrapping
element instead. One ref on the form covers every field, whatever the form grows to hold.

Reach for `inputRef` when you need a ref to one specific control. `TextInputField`, `CheckboxField`,
and `SwitchField` render a label, description, and error message around the control, so `inputRef`
is what reaches the input underneath. For `SelectField`, pass the library's ref through `triggerRef`
to reach the trigger button. A primitive that renders the control itself, such as `ComboboxInput`,
takes a plain `ref`.

## Submitting data

Prevent the browser's default submission in Form's `onSubmit`, then call `form.handleSubmit()`.
TanStack Form validates the values and calls `onSubmit` or `onSubmitInvalid`. Prefer `onSubmit` over
Form's `action` for this integration, because the library needs the submit event.
