Use the field primitives to build a custom field with Luke UI labels, descriptions, and validation
messages. Start with [`TextInputField`](/components/forms/text-input-field),
[`ComboboxField`](/components/forms/combobox-field),
[`SelectField`](/components/forms/select-field),
[`CheckboxField`](/components/forms/checkbox-field), or
[`SwitchField`](/components/forms/switch-field) when one of those components fits.

## Anatomy

`Field` provides the standard stacked anatomy: a label, the control, a description, and an error
slot. It always renders the error slot, so a validation message appears without extra markup.

`Field` provides presentation, not semantics. Render it inside a control root, such as
[`TextInputRoot`](/components/primitives/text-input) or
[`ComboboxRoot`](/components/primitives/combobox). The root connects the label, description, and
error to the control, so the parts need no manual ids.

`InlineField` is the counterpart for a control that carries its own label, such as
[`CheckboxRoot`](/components/primitives/checkbox) or [`SwitchRoot`](/components/primitives/switch).
It wraps the control's label part, such as `CheckboxLabel` or `SwitchLabel`, takes a `description`
and an `errorMessage`, and indents the error under the label text. Like `Field`, it needs a
surrounding control root.

`FieldLabel`, `FieldDescription`, and `FieldError` are the lower-level alternative for a custom
arrangement. Place them directly inside the control root, as the
[TextInput primitives](/components/primitives/text-input#choosing-a-composition) page shows. Use
either `Field`, `InlineField`, or the manual parts for one field, never a mix. Inside `CheckboxRoot`
or `SwitchRoot`, a `FieldLabel` replaces the text in `CheckboxLabel` or `SwitchLabel` and toggles
the control when clicked.

## Required fields

`necessityIndicator` controls the visible marker on `FieldLabel` and `InlineLabelText`. When
omitted, it inherits from the surrounding [`Form`](/components/forms/form). Without either setting,
required labels use `'required-asterisk'`.

The indicator does not make a control required. Set `isRequired` on the control root, or `required`
on an associated native input.

`isRequired` on `FieldLabel` or `InlineLabelText` describes the control's state for the marker. It
does not set the control's required semantics. Place it on the label part next to a native control
with `required`. Inside a Luke UI control root, the root's required state wins.

```tsx
<label>
	<input required type="checkbox" />
	<InlineLabelText isRequired>Accept the terms</InlineLabelText>
</label>
```

A composed `Field` named only through `aria-label` or `aria-labelledby` has no `label` to render, so
it shows no marker. Read [Required fields](/docs/forms#required-fields) for the three indicator
values and when to add a legend.

## Validation messages

Use `errorMessage` for validation feedback. `FieldError` shows the message, with a leading error
icon, while the surrounding control root is invalid.
