Use the field primitives to build a custom field with Luke UI labels, descriptions, and validation
messages. Start with [`TextInputField`](/components/forms/text-input-field) or
[`ComboboxField`](/components/forms/combobox-field) when one of those components fits.

<ExampleBlock src="field-primitive/basic" title="Field primitive: Basic" />

## Anatomy

`Field` provides the standard stacked anatomy: a label, the control, a description, and an error
slot. It always renders the error slot, so a validation message appears without extra markup.

`Field` provides presentation, not semantics. Render it inside a control root, such as
[`TextInputRoot`](/components/primitives/text-input) or
[`ComboboxRoot`](/components/primitives/combobox). The root connects the label, description, and
error to the control, so the parts need no manual ids.

`FieldLabel`, `FieldDescription`, and `FieldError` are the lower-level alternative for a custom
arrangement. Place them directly inside the control root, as the
[TextInput primitives](/components/primitives/text-input#choosing-a-composition) page shows. Use
either `Field` or the manual parts for one field, never both.

## Required fields

`necessityIndicator` changes the visible marker on `FieldLabel`. It does not make the control
required, so set the required state on the control root separately.

## Validation messages

Use `errorMessage` for validation feedback. `FieldError` shows the message, with a leading error
icon, while the surrounding control root is invalid.
