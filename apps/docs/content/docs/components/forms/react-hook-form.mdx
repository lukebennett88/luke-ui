title: React Hook Form
description: Wire a Luke UI field to React Hook Form with Controller.
---

Luke UI fields report a change as a value, through `onChange(value)`, not as a DOM event. React Hook
Form's `register` expects a native `onChange(event)`, so it does not fit a Luke UI field.
`Controller` does fit: it hands you a value and a setter and lets you decide how to wire them up.
This is the same pattern React Aria, React Spectrum, and Base UI document for their own value-based
fields.

## Wire a field with Controller

Pass `control` and a `name` to `Controller`. Its `render` prop hands you `field` and `fieldState`.
Spread `field`'s `value`, `onChange`, and `onBlur` onto the Luke UI field. Read `fieldState.error`
for the validation message.

```tsx
<Controller
	control={control}
	name="name"
	render={({ field, fieldState }) => (
		<TextField
			errorMessage={fieldState.error?.message}
			inputRef={field.ref}
			isInvalid={fieldState.invalid}
			label="Name"
			onBlur={field.onBlur}
			onChange={field.onChange}
			validationBehavior="aria"
			value={field.value}
		/>
	)}
	rules={{ required: 'Enter your name.' }}
/>
```

A checkbox works the same way. Map `field.value` to `isSelected` instead of `value`, since that is
the prop `Checkbox` reads.

```tsx
<Controller
	control={control}
	name="terms"
	render={({ field, fieldState }) => (
		<Checkbox
			errorMessage={fieldState.error?.message}
			inputRef={field.ref}
			isInvalid={fieldState.invalid}
			isSelected={field.value}
			onBlur={field.onBlur}
			onChange={field.onChange}
			validationBehavior="aria"
		>
			I accept the terms of service
		</Checkbox>
	)}
	rules={{ required: 'Accept the terms of service before you continue.' }}
/>
```

## Set validationBehavior to aria

Fields default to `validationBehavior="native"`: the browser blocks submission until every field
passes its own constraint validation. React Hook Form never gets a chance to run when the browser
blocks submission first, so `rules` messages never appear and `shouldFocusError` never fires.

Set `validationBehavior="aria"` on every field a `Controller` wraps. This hands validation to React
Hook Form and lets the browser mark the field for assistive technology instead of blocking submit.
Read [Validation](/components/forms/validation) for the full set of `validationBehavior` options.

## Pass field.ref to inputRef

Give `field.ref` to `inputRef`, not `ref`. `TextField` and `Checkbox` are composed fields: they
render a label, description, and error message around the control, so they take no plain `ref`.
`inputRef` is the only way to reach the underlying input, and it always resolves to that input,
never to a wrapper element around it.

If you drop down to a primitive that renders the control itself, such as `ComboboxInput`, give
`field.ref` to its `ref` prop instead.

## Focus the first invalid field on submit

React Hook Form focuses the first invalid field after a failed submission by default. It does this
through the ref each field registered, so a field that never received `field.ref` cannot be focused.
This is the main reason to wire up `inputRef`: without it, someone submitting an invalid form gets
an error message with no indication of where to look.

Set `shouldFocusError` to `false` on `useForm` to turn this off. Leave it on for every form where
someone fills in more than one field.

## Why not register

`register` returns an `onChange` that reads `event.target.value`. Luke UI fields never construct
that event: `onChange` receives the value directly, so a value-based field and an event-based
`onChange` cannot be connected. `Controller` exists in React Hook Form for exactly this case, and it
is the supported path for every Luke UI field.
