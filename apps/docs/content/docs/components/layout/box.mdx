`Box` accepts Luke UI layout properties and renders a `div` by default. It places content in a
layout, adds token spacing, constrains an element's size, or controls a flex child. Use a normal
`div` when no supported layout property applies.

<ExampleBlock src="box/basic" title="Box: Basic" />

## Choose a layout

Use Box for a custom flex layout or to control an item within a flex container. Use
[Grid](/components/layout/grid) to define grid tracks or areas, and its
[`GridItem`](/components/layout/grid#place-a-child) to place a child in a grid. Render a Box through
`GridItem`'s `renderRoot` to style a grid item. Read
[Layout](/docs/layout#choose-a-layout-component) to choose between layout components.

## Size and space content

Use sizing and spacing props to constrain content and set gaps, padding, or margins. Read
[Layout](/docs/layout#spacing-and-sizing) for the supported values. For a size outside those values,
read [Styling](/docs/styling#size-elements-outside-the-utility-values).

## Adapt to available space

Pass responsive values when a layout needs to change with its container. Read
[Layout](/docs/layout#responsive-values) for breakpoints and container behaviour.

## Choose the rendered element

Set `elementType` when the layout needs a supported structural element. The prop does not change
Box's accepted DOM props. Box owns the element and its DOM attributes.

The supported elements are `article`, `aside`, `dd`, `div`, `dl`, `dt`, `figcaption`, `figure`,
`footer`, `header`, `li`, `main`, `nav`, `ol`, `section`, `span`, and `ul`.

<ExampleBlock src="box/semantic-element" title="Box: Semantic element" />

## Remove list markers

Set `listStyle="none"` on a `ul` or `ol` Box to remove its markers. The element keeps its list
semantics. Browsers do not reset a list's margin and padding, so set them to `"0"` when the list
should not be indented. Safari with VoiceOver (WebKit) can drop list semantics when CSS removes the
markers, and adding `role="list"` restores them. Box and Stack never add the role for you.
`listStyle` accepts only `none` and has no responsive values. Stack accepts it too.

<ExampleBlock src="box/list-style" title="Box: List markers" />

## Own the rendered element

Use `renderRoot` when the callback must own the element and its DOM attributes. The callback
receives `domProps` containing resolved `children`, `className`, `style`, and a callback `ref` as
its first argument. Its second argument is an empty state object. Put other DOM attributes on the
element the callback returns. You may omit or replace supplied props. You then own the consequences.

Do not combine `renderRoot` with `elementType`. Use `Link` or `Button` when you need their
behaviour.

<ExampleBlock src="box/render-element" title="Box: Own the rendered element" />

Read [Composition](/docs/composition#render-a-different-dom-component) for the general `elementType`
and `renderRoot` rule.

## Contain scrolling

Set `overscrollBehavior="contain"` on a Box that scrolls, such as one with `overflowY="auto"`, to
stop the scroll from continuing to the page behind it once the Box reaches its end. The other value
is `auto`, the browser default. The prop accepts responsive values and works on the shared layout
components.

## Visual styles

Box accepts theme-backed background, border colour, radius, and shadow values, plus fixed border
width and style values. The values follow the [token reference](/docs/token-reference). Use a
component API for interaction states and typography. `boxShadow` accepts `inset`, `resting`,
`raised`, `floating`, and `overlay`, matching the `vars.shadow` leaves.

`backgroundColor` takes a standard surface, such as `surface.base`, or a role's resting fill, such
as `accent.subtle` or `accent.solid`. A solid value paints the role's resting fill, so
`accent.solid` is `vars.color.background.accent.solid.rest`. Box values never carry a state suffix,
so `accent.solid.rest`, `accent.solid.hover`, and `accent.solid.pressed` are not accepted. Use
`vars` for the hover and pressed fills. The background also sets the text colour that content inside
the Box inherits. Without `backgroundColor`, a Box keeps the colour it inherits. Read
[Colour](/docs/color#text-on-a-background) for the colours text reads on each background, and for
custom surfaces.

`borderColor="control"` is a guaranteed control boundary that reaches 3:1 against every surface and
every role's subtle background. It paints `vars.color.border.control.rest`. Box values are
state-free, so the `hover` and `pressed` borders are theme tokens for your own styles. Each role has
a `strong` border, such as `borderColor="warning.strong"`. It reaches 3:1 against the three surfaces
and that role's subtle background, not against arbitrary backgrounds. `borderColor="decorative"` is
a separator. Focus is not a border colour, so `borderColor` has no `focus` value. Box does not style
focus. When a custom element that is not a Box needs a colour, radius, or shadow value, use `vars`
from `@luke-ui/react/theme`. Read [Styling](/docs/styling#use-semantic-variables-for-custom-ui) for
when to reach for `vars`, and the [token reference](/docs/token-reference) for the contract.

Set `borderBlockStartWidth`, `borderBlockEndWidth`, `borderInlineStartWidth`, or
`borderInlineEndWidth` to `none`, `thin`, or `thick` to control a logical edge. These props override
`borderWidth` on that edge, including with responsive values. Set `borderStyle` as well: a width
alone does not make a border visible when the style is `none`. The edges follow the writing mode and
text direction.
