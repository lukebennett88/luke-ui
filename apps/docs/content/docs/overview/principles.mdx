---
title: Principles
description: Five decisions that keep Luke UI applications clear, accessible, and adaptable.
---

Use these principles to choose an API and understand which responsibilities stay with your
application.

## Start with the semantic component

Start with a semantic component such as `Button`, `Link`, or `TextField` when its purpose matches
the task. Use its supported props before you build a custom pattern.

## Compose from primitives when props do not fit

Primitives expose documented component parts without prescribing every arrangement. Preserve or
author the documented label, description, state, and control relationships in your composition.

## Style custom UI with public theme variables

Use `vars` from `@luke-ui/react/theme` for application-owned UI. Avoid generated selectors, palette
steps, and implementation-state attributes because they are not public contracts.

## Treat accessible behaviour as part of the contract

Luke UI supplies component mechanics and semantics. Applications supply meaningful names and
content, and they own the focus order of custom compositions.

## Respond to mode and viewport

Responsive `Box` and Sprinkles props adapt layout at breakpoints. Semantic values follow the active
identity and colour mode, while Luke UI defines its spacing and type steps in source.
