title: Applying a theme
description: Load Luke UI CSS and apply a theme identity and colour mode.
---

A themed subtree needs the shared Luke UI stylesheet, one identity stylesheet, and a root that
carries both theme classes. All three are static. Luke UI does not inject styles at runtime.

## Import the stylesheets

Import `@luke-ui/react/stylesheet.css` and the stylesheet for the identity your application uses.
The example below uses Tactile. Use `@luke-ui/react/themes/paper.css` with `paperThemeClassName` for
Paper. If you import one bundled identity, Luke UI does not load the other.

## Apply the root classes

Apply `themeRootClassName` and the matching identity class to the same element near the application
root. `themeRootClassName` includes the reset and base theme class. The identity class supplies the
semantic values.

<SourceCodeBlock src="theming/apply-theme" />

Theme identities do not nest. Use one identity for an application or an independent themed subtree.
A scope that needs a different identity becomes its own root.

## Choose a colour mode

Omit `data-color-mode`. The browser's `prefers-color-scheme` setting then selects the mode. Add
`data-color-mode="light"` or `data-color-mode="dark"` to a themed element when an application or
preview needs a fixed mode.

An explicit mode also sets the native `color-scheme` property. Browser controls and scrollbars then
match the Luke UI content.

## Nest colour-mode scopes

Colour modes nest within one theme identity. Use a nested mode for a preview, a dark page with a
light embedded document, or another intentional visual boundary. Do not add a second identity class
to the nested element.

## Avoid a colour-mode flash

Render the root classes and any known explicit mode in the server HTML. CSS can then select the
correct system mode before JavaScript runs. If a stored client preference may differ from the server
value, set the attribute before themed UI paints. A React effect runs after the first paint.

Keep the server fallback and hydrated value consistent to avoid a hydration warning.

## Preserve the theme in portals

Application-owned portals render outside the themed DOM branch. A CSS custom property set on the
themed root does not reach across that gap. Give the portal root the active identity class and the
explicit `data-color-mode` value, if there is one. If the source follows the system setting, leave
the attribute off the portal root too.

Luke UI's Combobox carries this contract to its own popover. It reads the trigger's identity class
and colour-mode attribute when the popover opens, and applies the same values to the popover root.
An application-owned portal needs to copy the same two values itself.
