# Make issue

Investigate and write an actionable GitHub issue. Investigating or drafting produces a draft. Create
or modify GitHub issues only when explicitly requested. Follow
[shared-rules.md](../shared-rules.md).

## Workflow

1. Establish the problem, constraints, and duplicates from code, tests, guidance, and issue history.
   Address existing issues before creating duplicates.
2. Describe current and desired behaviour, impact, settled decisions, acceptance criteria, and
   supporting evidence where useful. Give implementation enough context without reopening decisions.
3. Leave implementation flexible unless file changes, helpers, or architecture are settled or
   technically necessary.
4. For larger work, prefer coherent native GitHub sub-issues over duplicated Markdown progress
   checklists. Publishing or restructuring issues still requires authorisation.

Do not implement the issue, open a pull request, or review a diff.
